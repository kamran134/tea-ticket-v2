# Контекст: возврат оплаты

Кнопка «Вернуть деньги» в списке билетов админки. Право `tickets.refund`:
оно есть у Super Admin и у роли Admin (в том числе уже созданной — миграция
дописывает код в её список). У Manager права нет, пока его не выдадут в «Ролях».

Возвращаются только подтверждённые билеты, по которым ещё не отметили вход,
и только если у заказа есть успешная оплата картой. Ручное подтверждение без
платежа банк не вызывает.

Заказ группы — один платёж (`Payment.checkoutId` = `groupId`). Частичный
возврат — один вызов банка на сумму `price` выбранных билетов (то, что
реально списали, уже со скидкой). Остальные участники остаются `CONFIRMED`,
их QR и вход работают. Возвращённый билет — `REFUNDED`: место освобождается,
потому что этот статус не входит в живые брони. Когда возвращены все,
промокод заказа снова свободен: учёт использований смотрит только
`BOOKED` / `PENDING` / `CONFIRMED`.

Шлюз Kapital TXPG, документация «Execute Transaction / Refund»:
`POST /order/{id}/exec-tran` с телом
`{ tran: { phase: "Single", type: "Refund", amount } }`.
Авторизация та же Basic, что и у `GET /order/{id}`, пароль заказа не шлётся.
`voidKind: Partial` — это отмена авторизации (Order_DMS), у нас оплата сразу
(`Order_SMS`), поэтому частичный возврат группы делается суммой в `Refund`,
а не `voidKind`. Несколько таких вызовов допустимы, пока сумма не догонит
оплату; статус заказа `Refunded` банк ставит только на полный возврат, и мы
по-прежнему читаем его как успешный платёж, чтобы опрос не отменил заказ.
Недействительность билета хранится у нас в `Ticket.status`.

Два возврата одного платежа сериализуются блокировкой строки `Payment`.
Повтор уже возвращённого билета отклоняется до вызова банка.
