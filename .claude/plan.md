# План: Сетка = реальные зоны/места + зона без мест

## Концепция
«Сетка» (`GridMapEditor`) перестаёт быть черновиком-калькулятором поверх `Venue.gridLayout`
и становится редактором над настоящими `Zone`/`Seat`. Закрашенная ячейка — либо реальное
место (`Seat`, для `type: SEATED`), либо просто часть визуальной области зоны без мест
(`type: GENERAL`, вместимость — отдельное число). Сетка используется и на покупке билета
вместо «Схемы». «Схема» (`ZoneMapEditor`/`VenueMap`) скрывается из UI, код не удаляется.

# Часть 2: фикс синхронизации мест + убрать номер карты (заглушка оплаты)

## Баг
`PUT /:id/grid-layout` синхронизировал места для *всех* зон типа SEATED в мероприятии,
а не только для тех, что реально участвуют в сетке. Зона, созданная через старую
вкладку «Зоны» (генератор рядов/секций), никогда не красилась на сетке — при любом
сохранении сетки её места считались «удалёнными из сетки» и попадали под защиту от
удаления забронированного места → ошибка 409 на ровном месте.

## Этап 8: Backend
- [x] `venues.ts`: синхронизировать места только для зон, которые сейчас в `cells`
      ИЛИ были в *предыдущем* сохранённом `gridLayout` (а не для всех SEATED-зон венью)
- [x] `zones.ts`: `cardNumber` — необязательное поле в create/update схемах
- [x] `schema.prisma`: `Zone.cardNumber` — `@default("")`, миграция
- [x] `cron.ts`: отключить автоистечение BOOKED через 1 час — оно било в старый флоу
      «не оплатил за час», а без онлайн-оплаты подтверждение полностью ручное
